> **한 줄 요약** — 회원가입 화면을 Firebase와 연결해 **학생·사장님 두 유형 가입**, **페이지 이동 없는 아이디 중복 확인**, **비밀번호 해시 저장**을 구현했습니다.

## 배경 (Context)

이화픽은 학생이 마감 할인 상품을 예약하고, 사장님이 상품을 등록하는 서비스입니다. 상품 등록, 리뷰 작성, 좋아요 모두 **"누가 했는지"** 를 알아야 하므로 회원가입은 모든 기능의 출발점입니다. 처음 회원가입 화면은 모양만 있고 아무것도 저장되지 않았습니다.

## 목표 (Goal)

"저장만 되는" 회원가입이 아니라 실제 서비스처럼 동작하도록 세 가지 기준을 정했습니다.

| 기준 | 구현 방법 |
|---|---|
| 두 유형 지원 | 탭으로 학생/사장님을 고르면 필요한 입력 칸만 보이고 전송됨 |
| 빠른 피드백 | 가입 버튼을 누르기 전에 아이디 사용 가능 여부를 바로 표시 |
| 안전한 저장 | 비밀번호는 해시로 저장, Firebase 키는 GitHub에 올리지 않음 |

## 진행 단계 (Steps)

### 1단계. 설치와 Firebase 연결

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install flask pyrebase4
```

가상환경을 만들고 Flask와 Pyrebase4(파이썬용 Firebase 라이브러리)를 설치합니다. Firebase 콘솔 **프로젝트 설정 → 내 앱**의 설정값은 `authentication/firebase_auth.json` 에 저장하고, `.gitignore` 에 넣어 **키가 공개 저장소에 올라가지 않게** 했습니다.

```python
# database.py
class DBhandler:
    def __init__(self):
        config_path = Path(__file__).resolve().parent / 'authentication' / 'firebase_auth.json'
        with config_path.open(encoding='utf-8') as f:
            self.firebase = pyrebase.initialize_app(json.load(f))
```

DB 코드를 `DBhandler` 클래스 하나에 모아, `app.py` 는 함수 이름만 부르면 되게 했습니다.

### 2단계. 데이터 구조 설계: 아이디를 키로

회원 정보를 `user/<아이디>` 경로에 저장하기로 했습니다. 이 결정 하나로 중복 확인이 **조회 한 번**으로 끝납니다.

```python
# database.py
def user_duplicate_check(self, user_id):
    return self.db.child("user").child(user_id).get().val() is None

# app.py
@app.route("/check-id")
def check_id():
    user_id = request.args.get("user_id", "").strip()
    return jsonify(available=DB.user_duplicate_check(user_id))
```

값이 없으면(`None`) 쓸 수 있는 아이디이고, `/check-id` 는 그 결과를 JSON으로 돌려줍니다.

### 3단계. 새로고침 없는 중복 확인

```javascript
// signup.js
if (!/^[a-zA-Z0-9_]{4,20}$/.test(id)) {
  showMsg(idMsg, '영문, 숫자, _ 로 4~20자 입력해 주세요', false);
  return;
}
fetch(`/check-id?user_id=${encodeURIComponent(id)}`)
  .then((res) => res.json())
  .then((data) => showMsg(idMsg,
    data.available ? '사용할 수 있는 아이디예요' : '이미 사용 중인 아이디예요', data.available));
```

형식이 틀린 아이디는 서버에 묻기 전에 걸러서 불필요한 요청을 줄였습니다. 형식이 맞으면 `fetch()` 로 API를 불러 결과를 바로 보여 줍니다.

### 4단계. 해시 저장과 서버 쪽 재확인

```python
# app.py
@app.route("/signup_post", methods=["POST"])
def signup_post():
    data = request.form
    pw_hash = hashlib.sha256(data["password"].encode("utf-8")).hexdigest()
    if DB.insert_user(data, pw_hash):
        return redirect(url_for("login"))
    flash("이미 있는 아이디예요")
    return redirect(url_for("signup"))
```

비밀번호는 SHA-256 해시(64자리 문자열)로 바꿔 저장합니다.

```python
# database.py
def insert_user(self, data, pw_hash):
    if not self.user_duplicate_check(data["user_id"]):
        return False   # 버튼을 건너뛰고 제출해도 서버에서 한 번 더 막음
    user_info = {"id": data["user_id"], "pw": pw_hash,
                 "nickname": data["nickname"], "user_type": data["user_type"]}
    # 학생: 이화 메일(@ewha.ac.kr) / 사장님: 가게 이름·전화·주소 추가
    self.db.child("user").child(data["user_id"]).set(user_info)
    return True
```

화면의 검사는 사용자가 건너뛸 수 있으므로, **저장 직전에 서버에서 중복을 다시 확인**합니다. `user_type` 은 이후 로그인할 때 학생/사장님 메뉴를 나누는 기준으로 쓰입니다.

## 배운 점 (What I learned)

- **설계가 구현을 줄인다**: 아이디를 키로 정하자 중복 확인 코드가 한 줄이 됐습니다.
- **화면 검사와 서버 검사는 역할이 다르다**: 화면은 빠른 안내, 서버는 최종 방어선입니다.
- **다음 목표**: 지금은 SHA-256만 쓰지만, 같은 비밀번호도 다른 해시가 되도록 솔트(salt)를 더하는 방식을 공부해 적용해 보고 싶습니다.
