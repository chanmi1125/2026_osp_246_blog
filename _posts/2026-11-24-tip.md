## 배경

이화픽은 이화인을 위한 마감 할인 상품 픽업 서비스로 학생은 상품을 둘러보고 리뷰를 작성하고 사장님은 상품을 등록하고 예약을 관리한다. 두 계정 모두 헤더의 버튼을 눌러 옆에서 열리는 메뉴를 사용하지만 메뉴를 열었을 때 바로 가야 하는 페이지는 계정에 따라 다르다.

예를 들어 학생 메뉴에는 상품 목록과 리뷰 목록이 들어간다. 사장님 메뉴에는 예약 관리와 상품 등록이 들어간다. 항목은 다르지만 메뉴의 제목 영역, 링크를 나열하는 방식, 닫기 버튼은 두 계정에서 공통으로 쓰인다. 이화픽에서는 역할에 따라 달라지는 값과 공통 HTML을 파일 단위로 나눴다.

## 목표

사장님 메뉴에만 항목을 추가한다면 사장님용 목록에서 바꿀 위치를 찾을 수 있어야 한다. 반대로 링크의 공통 모양을 바꾼다면 공통 템플릿 한 곳에서 수정할 수 있어야 한다. 이를 위해 기본 레이아웃에서 역할별 파일을 선택하고, 역할별 파일 안에서 값을 설정한 뒤 동일한 메뉴 템플릿을 불러온다.

## 적용 단계

### 1. 기본 레이아웃에서 역할별 메뉴 파일을 선택

`pages/core/base.html`에는 헤더와 본문을 배치하는 공통 구조가 있다. `app.py`의 `auth_context()`는 로그인한 사용자의 세션에서 `user_type`을 읽어 템플릿에 `auth_role`로 전달한다. 헤더 아래에서는 `auth_role`이 `student`이면 학생 메뉴 파일을, `owner`이면 사장님 메뉴 파일을 불러온다. 두 값에 해당하지 않는 경우에는 이 분기에서 역할별 메뉴를 출력하지 않는다.

{% raw %}
```jinja
{% if auth_role == "student" %}
  {% include "core/menu_student.html" %}
{% elif auth_role == "owner" %}
  {% include "core/menu_owner.html" %}
{% endif %}
```
{% endraw %}

이 분기를 기본 레이아웃에 두면 각 페이지에 같은 조건문을 붙일 필요가 없고 상품 상세나 상품 등록처럼 본문이 다른 페이지도 기본 레이아웃을 통해 같은 방식으로 메뉴를 선택한다.

### 2. 역할별 파일에서 메뉴에 들어갈 값을 정한다

`pages/core/menu_student.html`은 아래처럼 학생용 메뉴 목록을 정의한다. 각 항목에는 Flask 엔드포인트 이름, 화면에 보이는 문구, 배지 문구, 배지 종류가 순서대로 들어간다. 학생 메뉴의 이 항목들은 배지를 표시할 필요가 없어 마지막 두 값을 `None`으로 둔다.

{% raw %}
```jinja
{% set menu = [
  ("product_list", "상품 목록", None, None),
  ("review_list", "리뷰 목록", None, None),
  ("review_write", "리뷰 작성", None, None),
  ("student_mypage", "마이페이지", None, None),
] %}
{% include "core/drawer.html" %}
```
{% endraw %}

사장님용 `pages/core/menu_owner.html`도 같은 구조를 사용한다. 예를 들어 첫 항목은 예약 관리 페이지를 가리키는 `("owner_reservations", "예약 관리", "3", "count")`는데 여기서 `"3"`은 사장님용 템플릿에 지정한 배지 문구다. 두 파일은 메뉴 목록 외에도 메뉴의 접근성 이름과 홈·프로필 링크에 사용할 엔드포인트를 설정한다. 마지막에는 둘 다 같은 `drawer.html`을 불러온다. Jinja의 `include`는 기본적으로 현재 템플릿의 변수를 전달한다. 그래서 공통 템플릿에서도 각 역할의 파일이 `set`으로 정의한 `menu`를 읽을 수 있다.

### 3. 공통 템플릿에서 메뉴 링크를 만든다

`pages/core/drawer.html`은 메뉴 항목을 하나씩 꺼내서 링크를 만든다. 아래 코드에서 `url_for(endpoint)`에 전달하는 값은 역할별 파일에서 정의한 Flask 엔드포인트 이름으로 현재 요청의 엔드포인트와 일치하는 링크에는 강조 스타일을 적용하는 `active` 클래스와 현재 페이지임을 알리는 `aria-current="page"`가 붙는다. 배지 문구가 있는 항목에만 배지가 표시된다.

{% raw %}
```jinja
{% for endpoint, label, badge, badge_kind in menu %}
<li><a href="{{ url_for(endpoint) }}" {% if request.endpoint == endpoint %}class="active" aria-current="page"{% endif %}>
  <span class="menu-label">{{ label }}</span>
  {% if badge %}<span class="badge badge-{{ badge_kind }}">{{ badge }}</span>{% endif %}
  <span class="chevron" aria-hidden="true">&rsaquo;</span>
</a></li>
{% endfor %}
```
{% endraw %}

이로써 메뉴 항목을 어디서 수정할지 판단하기 쉬워진다. 학생 메뉴의 표시 문구를 바꾸려면 학생용 목록을 수정하고 두 메뉴에서 현재 페이지를 표시하는 방식을 바꾸려면 공통 템플릿의 링크 출력 부분을 수정하면 된다.

## 결과 확인

학생 계정으로 상품 목록에서 메뉴를 열면 **상품 목록**이 현재 페이지로 강조되고 **리뷰 목록**, **리뷰 작성**, **마이페이지**가 표시된다. 사장님 계정으로 예약 관리에서 메뉴를 열면 **예약 관리**가 강조되고 **상품 등록**, **받은 리뷰**, **마이페이지**가 표시된다. 두 화면에서 메뉴의 구조는 같고, 역할별 항목과 배지가 달라지는 모습을 확인할 수 있다.

## 배운 점

두 화면에서 비슷한 HTML이 반복될 때는 먼저 무엇이 달라지는지 확인하면 공통으로 묶을 범위를 정하기 쉽다. 이화픽 메뉴에서 달라지는 값은 항목의 이름과 목적지였고, 링크 만드는 방식은 같았다. 역할별 메뉴를 늘리거나 항목을 바꿀 때도 이 기준으로 수정할 파일을 찾을 수 있다.
