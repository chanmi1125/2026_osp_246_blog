## 배경 (Context)

이화픽(EWHA PICK)은 이화인을 위한 마감 할인 상품 픽업 마켓입니다. 그중 상품 상세페이지에서는 사용자가 선택한 상품의 가격, 픽업 시간, 남은 수량, 판매 상태 등의 구매에 필요한 구체적인 정보를 확인하고 예약 여부를 결정할 수 있습니다.

이번 팀 프로젝트에서는 기존에 구현된 상품 상세페이지와 Firebase에 저장된 상품 데이터를 연동하는 작업을 담당했습니다. 상품 상세페이지는 동일한 화면 구조를 사용하지만, 사용자가 선택한 상품에 따라 서로 다른 정보가 표시되어야 합니다.

이를 위해 기존 Flask 라우팅 구조를 활용하여 사용자가 선택한 상품의 정보를 Firebase에서 조회하고, 해당 정보를 상품 상세페이지에 전달하도록 연동했습니다.

이 글에서는 상품을 선택하는 시점부터 데이터베이스에 저장된 정보가 사용자 화면에 표시되기까지의 동작 원리를 설명하고자 합니다.

## 기능 소개 (Goal)

상품 상세페이지는 사용자가 상품 목록에서 선택한 상품의 구체적인 정보를 확인하고 예약 여부를 결정할 수 있는 페이지입니다. 사용자는 상품 이미지, 상품명, 정가, 할인율, 할인 적용 가격을 확인할 수 있으며, 판매자의 가게 정보와 픽업 가능 시간, 남은 재고, 상품 설명 등을 살펴볼 수 있습니다.

상품 상세페이지에서 이용할 수 있는 주요 기능은 다음과 같습니다.

- **상품 정보 확인:** 상품 이미지, 상품명, 상품 설명, 정가, 할인율 및 할인 적용 가격을 확인할 수 있습니다.
- **픽업 정보 확인:** 가게 위치와 픽업 가능 시간을 확인할 수 있습니다.
- **리뷰 확인 및 작성:** 상품의 평균 평점과 리뷰 수를 확인할 수 있으며, 전체 리뷰 목록이나 해당 상품의 리뷰 작성 페이지로 이동할 수 있습니다.
- **좋아요:** 로그인한 사용자는 관심 있는 상품에 좋아요를 표시할 수 있습니다.
- **예약 수량 선택:** 판매 중이고 재고가 남아 있는 상품은 남은 재고 범위 내에서 원하는 수량을 선택할 수 있습니다.
- **합계 금액 확인:** 선택한 수량에 따라 변경되는 합계 금액을 확인할 수 있습니다.

이러한 기능을 통해 사용자는 상품에 대한 충분한 정보를 확인하고 조건을 고려하여 자신에게 필요한 상품을 선택할 수 있습니다.

### 문제 및 목표 (Problem or goal)

상품 상세페이지는 사용자가 어떤 상품을 선택하느냐에 따라 표시되는 정보가 달라져야 합니다. 그러나 상품마다 별도의 HTML 파일을 작성하는 방식은 새로운 상품이 등록될 때마다 페이지를 추가해야 하므로 관리가 어렵습니다.

이를 해결하기 위해 기존 Flask 라우팅 구조와 Firebase 상품 조회 기능을 활용하여, 사용자가 선택한 상품의 정보가 기존 상세페이지에 동적으로 표시되도록 연동하는 것을 목표로 하였습니다.

구체적인 목표는 다음과 같습니다.

- 상품 목록에서 선택한 상품의 이름을 Flask에 전달합니다.
- 상품 이름을 기준으로 Firebase에 저장된 정보를 조회합니다.
- 조회한 상품 정보를 기존 HTML 템플릿에 전달합니다.
- 하나의 상세페이지에서 선택한 상품에 따라 서로 다른 정보를 표시합니다.

## 구현 과정 (Steps)

### 화면 구성

상품 상세페이지는 크게 상품 이미지 및 할인 정보, 가게 및 픽업 정보, 상품 설명 및 리뷰 작성 링크, 예약 영역으로 구성되어 있습니다.

![상품 상세페이지 화면]({{ '/assets/images/explanation-2/product-detail.png' | relative_url }})
*그림 1. 크림치즈 베이글 상품의 상세페이지*

상품 상세페이지의 동작에 관련된 주요 파일은 다음과 같습니다.

| 파일 | 역할 |
|---|---|
| `product_list.html` | 선택한 상품의 상세페이지로 이동하는 링크를 제공합니다. |
| `app.py` | 상세페이지 요청을 처리하고 상품 정보를 템플릿에 전달합니다. |
| `database.py` | Firebase에 저장된 상품 정보를 조회합니다. |
| `product_detail.html` | 전달받은 정보를 화면에 표시합니다. |
| `product_detail.css` | 상세페이지의 디자인과 배치를 담당합니다. |
| `product_detail.js` | 좋아요 및 예약 수량 변경 등 화면의 동작을 처리합니다. |

Flask는 사용자의 웹 요청을 처리하는 Python 웹 프레임워크입니다. Firebase Realtime Database는 상품 정보가 저장되는 공간이며, Jinja2는 Python에서 전달받은 값을 HTML에 표시하는 템플릿 엔진입니다. 이 글에서는 기존 화면과 데이터베이스를 연결하는 과정에 집중합니다.

### 동작 흐름

크림치즈 베이글을 선택하는 상황을 예로 들어 보겠습니다. 상품을 클릭하면 상품 이름이 포함된 URL을 통해 Flask에 요청이 전달됩니다. Flask는 기존 데이터베이스 조회 함수를 호출하여 해당 상품의 정보를 가져옵니다. 서버에서 준비된 정보는 Jinja2를 통해 상세페이지에 표시됩니다.

전체 과정은 다음과 같습니다.

1. 학생이 상품 목록에서 크림치즈 베이글을 선택합니다.
2. Flask가 상세페이지 요청을 받아 상품 이름을 확인합니다.
3. Firebase의 `item` 노드에서 해당 이름의 상품 정보를 조회합니다.
4. Flask가 화면에 필요한 상품 정보를 HTML 템플릿에 전달합니다.
5. Jinja2가 상품 이름과 가격 등의 값을 HTML에 넣어 사용자에게 보여 줍니다.

다른 상품을 선택하더라도 HTML 파일은 바뀌지 않습니다. 조회하는 상품 데이터만 달라지기 때문에 동일한 템플릿을 사용할 수 있습니다.

### 핵심 코드

#### 1. 선택한 상품 이름 전달하기

상품 목록의 `product_list.html`에서는 각 상품의 상세페이지로 이동하는 링크에 해당 상품의 이름을 포함합니다. 아래 코드는 링크의 `href` 속성을 발췌한 것입니다.

{% raw %}
```html
href="{{ url_for('product_detail', name=product.name) }}"
```
{% endraw %}

`url_for()`는 Flask 함수에 연결된 URL을 생성합니다. `product_detail`은 상세페이지 요청을 처리하는 함수 이름이며, `name=product.name`은 사용자가 선택할 상품의 이름을 전달한다는 의미입니다. 따라서 상품마다 서로 다른 링크가 만들어집니다.

#### 2. Flask 라우팅과 Firebase 연동

`app.py`의 `product_detail()` 함수는 상품 상세페이지 요청을 처리합니다. 아래는 상품을 식별하고 조회하는 부분입니다.

```python
@app.route("/products/<int:product_id>")
@app.route("/products/<name>")
def product_detail(product_id=None, name=None):
    product = None

    item_name = name if name is not None else str(product_id)
    info = DB.get_item(item_name)
```

라우팅은 특정 URL을 해당 요청을 처리하는 함수와 연결하는 과정입니다. 현재 코드는 숫자 ID를 사용하는 경로와 상품 이름을 사용하는 경로를 모두 지원합니다. 상품 이름이 전달되면 이를 `item_name`에 저장하고, 이름이 없으면 숫자 ID를 문자열로 변환하여 조회에 사용합니다.

`DB.get_item(item_name)`은 기존 Firebase 조회 함수를 호출하는 부분입니다. 예를 들어 크림치즈 베이글을 선택하면 해당 상품 이름을 기준으로 데이터베이스를 조회합니다.

다음은 `database.py`에 정의된 기존 조회 함수입니다.

```python
def get_item(self, name):
    """상품 이름을 키로 조회. 없으면 None."""
    return self.db.child("item").child(name).get().val()
```

Firebase에서는 데이터를 노드 단위로 관리합니다. `child("item")`은 상품 정보가 저장된 위치에 접근하고, `child(name)`은 그중 선택한 상품에 접근합니다. `get().val()`은 해당 위치에 저장된 실제 값을 가져옵니다. 상품이 존재하지 않으면 `None`이 반환됩니다. 이미 마련된 조회 함수를 활용하면 데이터베이스 접근 코드를 상세페이지에서 다시 작성하지 않아도 됩니다.

![Firebase 상품 데이터]({{ '/assets/images/explanation-2/firebase-item.png' | relative_url }})
*그림 2. Firebase Realtime Database에 저장된 크림치즈 베이글의 상품 데이터*

그림 2는 Firebase에 실제로 저장된 크림치즈 베이글의 상품 정보입니다. 정가(`price`)는 3200, 할인율(`discount_rate`)은 30, 남은 수량(`quantity`)은 4로 저장되어 있습니다. 또한 픽업 시간과 판매 상태 등의 정보도 함께 저장되어 있습니다.

Flask는 상품 이름을 기준으로 이러한 정보를 조회하며, 조회된 데이터는 상품 상세페이지에 표시되는 정보의 기반이 됩니다.

#### 3. 조회한 정보를 상세페이지에 전달하기

상품 정보가 존재하면 현재 프로젝트의 `product_detail()` 함수는 화면에 사용할 `product` 데이터를 구성합니다.이 과정에서 `Firebase`에 저장된 정가와 할인율을 이용하여 할인 적용 가격을 계산합니다. 예를 들어 크림치즈 베이글의 정가는 `3,200`원이고 할인율은 `30%`이므로, 할인 적용 가격은 `2,240`원이 됩니다.

```python
return render_template("student/product_detail/product_detail.html", product=product)
```

`render_template()`은 지정된 HTML 템플릿을 렌더링하는 Flask 함수입니다. `product=product`를 통해 Python에서 준비한 상품 정보를 HTML에서도 `product`라는 이름으로 사용할 수 있습니다.

아래는 기존 `product_detail.html`에서 상품 이름과 가격을 표시하는 코드입니다.

{% raw %}
```html
<h1 class="detail-name">{{ product.name }}</h1>
<strong class="current-price">
  {{ "{:,}".format(product.price) }}원
</strong>
```
{% endraw %}

Jinja2는 중괄호 안의 표현식을 실제 데이터로 바꿉니다. `product.name`에는 상품 이름이, `product.price`에는 할인 적용 가격이 들어갑니다. 가격에는 천 단위 쉼표도 적용됩니다. 예를 들어 할인 가격이 2240이면 화면에는 2,240원으로 표시됩니다.

상품 정보가 없는 경우에는 기존 HTML의 조건문을 통해 상품을 찾을 수 없다는 안내를 표시합니다. 이처럼 서버가 전달하는 값에 따라 화면의 내용이 달라집니다.

### 예약 수량 및 합계 금액 변경

![예약 수량 변경 화면]({{ '/assets/images/explanation-2/quantity.png' | relative_url }})
*그림 4. 예약 수량을 2개로 변경한 화면*

기존 상세페이지에 구현된 수량 조절 기능을 사용하면 선택 수량에 맞춰 합계 금액도 변경됩니다. 수량을 1개에서 2개로 늘리면 합계는 2,240원에서 4,480원으로 바뀝니다. 이 기능은 JavaScript에서 처리하며, 현재 예약 완료 화면 이동은 실제 결제나 데이터베이스의 재고 차감까지 수행하지 않습니다.

### 상품 정보가 존재하지 않는 경우
![상품을 찾을 수 없는 화면]({{ '/assets/images/explanation-2/product-not-found.png' | relative_url }})
*그림 5. 존재하지 않는 상품에 접근했을 때의 안내 화면*

Firebase에 존재하지 않는 상품 이름으로 상세페이지에 접근하면 상품 조회 함수는 `None`을 반환합니다. 이 경우 HTML 템플릿의 조건문에 따라 상품을 찾을 수 없다는 안내 문구가 표시됩니다.

이를 통해 상품 정보가 존재하는 경우뿐만 아니라 존재하지 않는 경우에도 조회 결과에 따라 적절한 화면이 표시되는 것을 확인할 수 있습니다.

## 배운 점 (What I learned)

기존 Flask 라우팅과 Firebase 조회 함수를 활용하여 상품 상세페이지에 데이터를 연동하면서 웹 요청부터 화면 출력까지의 연결 구조를 이해할 수 있었습니다. 특히 하나의 HTML 템플릿에 서로 다른 데이터를 전달하면 여러 상품의 상세 정보를 표시할 수 있다는 점을 배웠습니다. 또한 기존 화면과 데이터를 연결할 때 상품을 식별하는 기준과 템플릿에 전달하는 변수의 이름을 일관되게 유지하는 것이 중요하다는 점을 알게 되었습니다.
